# 2026-05-01 — Bypass de-promotion + telemetry loop

## Context
Audited why agents kept burning savings with `TRS_SKIP=1 grep …`,
`TRS_SKIP=1 npm test`, and similar defensive bypass calls on
routine commands. Root cause: bypass mechanisms (`trs raw`,
`TRS_SKIP=1`) were promoted in agent-facing surfaces — the
`~/.claude/trs.md` template, `docs/llms.txt`, the README headline.
The previous v0.5.14 fix tried strengthening "Do NOT use" guidance;
agents kept reaching for the escape hatch anyway. Negative
instructions are weaker than absence; the visibility itself is the
temptation.

This session removed bypass mentions from prompt-level surfaces
(silent strategy) and added telemetry so the user can measure
whether the strategy is working.

## Decisions

### Silent removal vs strengthened "Do NOT" guidance
Previous v0.5.14 fix added louder "Do NOT use trs raw for
routine commands" with an explicit list of forbidden routines.
Outcome: agents ignored it. New approach: remove the mention
entirely from prompt-level surfaces; bypass mechanisms still
exist in `trs --help` and human-facing docs.

Reasoning: every word an agent reads about a feature is an
invitation to use it. Less visibility beats stronger negation.
The `trs raw` subcommand and `TRS_SKIP=1` env var were kept
fully functional — only their promotion to AI-agent-facing
surfaces was cut.

### Skipped: hot-path double-walk refactor
`build_hook_response` now calls `cmd_bypasses_trs` before
`maybe_rewrite`; both walk leading env-prefixes. A code-review
pass flagged this as a hot-path "critical" issue and proposed
converting `maybe_rewrite` to return a discriminated
`RewriteResult { Bypass, Rewrite, Skip }` enum so the walk
happens once.

Rejected: the actual cost is ~30ns per multi-env command vs
~100µs for the hook itself (~0.03% overhead). The refactor
would force every recursive call site of `maybe_rewrite`
(chain handling, env-prefix unwrap) to explicitly disambiguate
`Bypass` from `Skip`, which today collapse to `None`. Permanent
cognitive complexity for invisible performance gain.

### Telemetry shape: bool field vs separate log file
Bypass entries land in the same `history.jsonl` as normal
executions, distinguished by `bypass: Some(true)`. Alternative
(separate `bypass.jsonl`) was rejected because it would split
the data model and force `stats --by-agent` to read two files.
Zero byte counts on bypass entries mean they don't perturb
savings sums; only counts.

### Kept `docs/features/init.md` "Bypassing" section as-is
The section explains `TRS_SKIP=1` to readers of usetrs.dev. It
uses human-framed language ("Sometimes you want the agent to get
raw command output") and lives in the docs site, not in any
prompt that ships to agents. Removing it would lose useful
human-facing documentation without changing the strategic
picture.
