## Decisions

### Import resolution strategy
Unified `resolve_imports` router dispatches based on import shape:
- `./`/`../`/`@/` → `resolve_relative` (path normalization or suffix match)
- Contains `/` → `resolve_module_path` (last 2 then 1 components)

### Go test error message buffering
Go test `-v` outputs error lines BEFORE `--- FAIL:`, not after. Initial design collected errors
after the FAIL marker. Fixed by buffering lines between `=== RUN` and the result line.

### Docs project detection
Projects with >50% `.md`/`.txt` files are classified as docs/skills — dep summary is suppressed
(no source imports to detect, header would be empty noise).

# 2026-04-17 — v0.5.6 qualitative polish: 9-agent integration audit

## Context
Post-v0.5.5 head-to-head benchmark (trs vs rtk 0.35.0) surfaced two
real bugs plus a systemic gap: some cases where rtk "won" were actually
silent information loss (dropped remote branches, truncated commit
messages). Fixed our equivalents honestly (reformat, never drop), then
ran every one of the 9 supported agent integrations end-to-end. Found
and fixed bugs in 6 of the 9. Documented the whole architecture in
`docs/agent-integrations.md`.

## Completed

### Ingest: minimal ≠ aggressive (bug, PR #14)
- `dc5b66d` — both levels fell through the same wildcard arm calling
  `extract_signatures`; now `minimal` delegates to `filter_minimal`
  (strip comments + normalize blanks) while `aggressive` keeps the
  signatures-only behavior.
- labs-tarscli measured: full 334k tokens / minimal 272k / aggressive 18k.

### git branch -a grouping (feature, PR #14)
- `d490ae6` — parser stripped `remotes/` and de-duped but printed every
  branch individually. Added prefix-grouping with `+N more` collapse at
  `COLLAPSE_THRESHOLD=3`, `NAMES_SHOWN_PER_GROUP=2`.
- Compression: native 1148B → trs 262B (77%). Was 14% before.

### git log: remove silent commit-message truncation (fix, PR #14 part)
- `15b4c2a` — two call sites truncated subjects to 57 chars + "..."
  unconditionally. Removed by default. Added opt-in `--truncate N` flag
  for the `parse git-log` handler.
- Default now preserves full messages; users who want tighter output
  pass `--truncate 80`.

### Gemini CLI hook format fix
- `a662c9d` — our `trs rewrite` always emitted Claude Code's
  `hookSpecificOutput.updatedInput.command` envelope. Gemini silently
  ignored that shape — it expects `hookSpecificOutput.tool_input.command`
  with a top-level `decision`. Symptom: hook fired (exit 0) but command
  was never rewritten; `trs stats` showed no entries.
- Added `hook_event_name` dispatch: `PreToolUse` → Claude, `BeforeTool`
  → Gemini, `preToolUse` → Cursor (later), default → Claude.
- Validated with a debug-wrapper that logged stdin/stdout of the hook.

### Factory Droid matcher widening
- `af5b783` — Droid's shell tool is `Execute`, not `Bash`. Our template
  copied Claude's `matcher: "Bash"` verbatim, so the hook registered but
  never matched. Widened to `matcher: ".*"` in a dedicated `DROID_HOOKS`
  template. `trs rewrite` already filters non-shell input, so the wider
  matcher is safe.

### Stale-hook upgrade in merge_json_hook
- `62b83de` — `merge_json_hook` skipped re-writing when any existing
  `trs rewrite` entry was found, which blocked template upgrades (e.g.
  the Droid matcher widening). Now removes any existing trs-owned
  entries across all events and re-adds from the template. User-added
  entries (notify scripts, etc.) survive untouched. Idempotency
  preserved via a before/after snapshot compare.

### OpenCode plugin API + path (fix)
- `b3d783f` — two stacked bugs:
  - Plugin code used `before_tool_call` hook with `ctx.tool` / `ctx.input`.
    Actual API is `"tool.execute.before"` with `(input, output)` and
    `input.tool === "bash"`. Rewritten `OPENCODE_PLUGIN`.
  - `global_dir` was `None`, so `--global` fell back to writing
    `.opencode/plugins/trs.ts` in cwd. Fixed to
    `~/.config/opencode/plugins/`.
- Confirmed end-to-end: plugin auto-discovered, `git status` compressed
  via `trs git status`, stats tracked.

### Kilo plugin path (same fix as OpenCode)
- `e775873` — identical architecture to OpenCode; same
  `global_dir: None` → `.config/kilo/plugins`.

### Pipe/redirect first-segment rewrite (feature, PR #14)
- `7e25b53` — agents routinely add `| head -N`, `| grep X`, `> out.txt`
  to cap output. Old logic skipped rewrite entirely on pipe — defeated
  trs for those very common cases. Now splits at the first operator
  and rewrites only the producer segment (`git status | head -3` →
  `trs git status | head -3`). Semicolons still skip.

### install.sh zshenv targeting
- `6f84f62` — zsh's non-interactive / non-login shells (what IDE tool
  subprocesses usually are) read `.zshenv`, not `.zshrc`. Our previous
  install instructed users to add PATH to `.zshrc`, which left IDE
  subshells broken (`command not found: trs` in Antigravity). Target
  `.zshenv` for zsh instead. `ANTIGRAVITY_RULES` also got a fallback
  section pointing at the absolute `$HOME/.local/bin/trs` path.

### Cursor: move from beforeShellExecution → preToolUse (fix)
- `fb4bafb` + `e797d8a` — Cursor's `beforeShellExecution` hook ONLY
  supports allow/deny/ask decisions; it cannot rewrite the command.
  The rewrite-capable hook is `preToolUse` (lowercase first letter,
  different from Claude's `PreToolUse`). Moved the template;
  introduced the `preToolUse` arm in the dispatch. Added
  `matcher: "Shell"` in a follow-up because Cursor fires `preToolUse`
  for every tool including Read — observed 551 hook invocations in a
  short session before the matcher.

### Post-review cleanup
- `d6301ae` — `apply_truncate` delegates to `helpers::truncate`
  instead of re-doing the char-boundary walk; added a `has_shell_op`
  byte-scan fast path in `maybe_rewrite` (cuts 3-4 `contains` scans

  an `HookEvent` enum.
- `1e332ac` — replaced three ad-hoc `truncate_*` helpers
  (`stats::truncate_cmd`, `replace::truncate_line`,
  `parse::extra_services::truncate_str`) with delegates to
  `helpers::truncate`. Each used `&s[..max_len.saturating_sub(3)]`
  which panics on char boundaries — latent UTF-8 bug fixed as a
  side effect.
- `cb35c9f` — renamed `HookEvent::from_wire` to `HookEvent::parse`
  (idiomatic Rust).

## Decisions

### Honesty over compression
When trs and rtk produce different byte counts, verify WHAT each
strips. rtk's "wins" on `git branch -a`, `git log`, and `find` all
came from silently dropping information (all remote branches,
truncated commit subjects, "+N more" with a 50-item cap). We
consolidated via reformatting and grouping instead (prefix grouping
on branches, optional explicit truncation on log, full file list
with summary on find). Net: we lose ~5-10 percentage points on raw
byte compression, but never lose grep-ability.

### Three output envelopes, one input envelope
All hook/plugin clients send `tool_input.command`; three emit
different response shapes. Rather than a single "canonical" output,
dispatch per `hook_event_name`. An enum is cheaper than a
trait-object and exhaustive: `HookEvent::{ClaudePreToolUse,
GeminiBeforeTool, CursorPreToolUse}`. New clients = new variant +
new match arm + new wire-name parse rule.

### merge_json_hook: sweep across ALL events
Template migrations (Cursor `beforeShellExecution` →  `preToolUse`)
leave orphaned entries on the old event name if the sweep is scoped
to the template's events. Now cleans any `trs rewrite` entry
anywhere in the `hooks` object before re-inserting from the
template. Safe because each template writes to its own file — no
cross-tool contamination risk.

### Rules-based: describe, don't force
Codex, Antigravity, and Windsurf have no programmatic hook. The
rules files SHOULD describe what trs is and WHEN to use it (token
minimization context), not try to force every command through trs.
The agent decides. Test prompts for these agents validate the
agent's voluntary choice, not mechanical interception.

# 2026-04-18 — v0.5.7: feedback branch — handlers + safety + docs audit

## Context
Post v0.5.6 release, user began running trs in real projects (cameraman,
labs_irma_portafolio, labs-newbase, others). Each new session of use
surfaced one more gap — commands with 0% reduction that deserved a
handler, safety cases where compression ate useful info, or visibility
questions (`trs stats` didn't make trends obvious). Branch accumulated
fixes iteratively as feedback came in, ending with a bigger feature
(`trs audit-docs`) motivated by the observation that agent instruction
files (CLAUDE.md / AGENTS.md / .windsurfrules) silently inflate every
session's token budget.

## Completed

### `trs stats` — explicit date range + today + last command + history hint

  timestamps: `Apr 15 23:04 → Apr 18 17:12 (3 days)`

- "For full history: trs stats --history" footer makes the detail view

### Credential preservation (NOT redaction)
- `common::contains_credential` flags AWS keys (AKIA/ASIA/aws_secret_…),

  Bearer / Authorization / X-Api-Key headers, URL basic-auth, JWTs, PEM
  private keys, URL password params.
- handle_build collects credential-bearing lines into a third bucket
  and emits them as "preserved (N credential-bearing):". Debug info
  survives even when compression would otherwise strip the line.

### `trs audit-docs` — new command for static analysis of agent docs
Walks CLAUDE.md / AGENTS.md / GEMINI.md / CURSOR.md / .windsurfrules /
.cursor/rules/ / .agent/rules/ / .codex/rules/ and surfaces:

- Per-file token estimate (weighted-character heuristic: ASCII 0.22,
  whitespace 0.08, CJK 0.66) + last-git-touch date.
- Cross-file near-duplicate blocks via 64-bit SimHash over 3-word shingles
  (Hamming ≤6 ≈ ≥90% similarity). Skips single-line / <60-char blocks
  to avoid heading-only noise.
- Dead references — `@imports` + markdown `[text](./path)` targets that
  don't exist on disk. Tight `@import` heuristic (require ./ or ../ or
  recognized file extension) avoids flagging npm-scope packages as
  broken paths.
- Embedded reference content — fenced code blocks above a threshold
  (20 lines generic, 10 lines for SQL/JSON/YAML/GraphQL/XML/HTML) and
  markdown tables with ≥8 data rows. Each gets a per-kind
  recommendation (move queries to docs/queries.sql, extract schema
  to docs/schema.graphql, etc.).
- Symbol cross-reference — for flagged code fences in ts/tsx/js/jsx/py/
  rs/go/swift, extract function/class/export names, then walk the
  project source (via `ignore` crate, 2000-file cap) to find which
  names actually live in source. Emits per-block:
    ▸ REMOVE from doc — N of M symbols already in source:
        handleSubmit → ./app/dashboard/settings/page.tsx
    ▸ EXTRACT — N symbol(s) not found in source: createSchema, ...
  Ultra-generic names (data/result/page/value/…) filtered via a 60-entry
  blocklist to keep false-positive rate down.

### audit-docs integration points
- `trs doctor` now scans the cwd for CLAUDE.md / AGENTS.md over 5k
  tokens and emits a warn: "run `trs audit-docs` to find duplicates /
  dead refs / embedded bloat".
- CODEX_AGENTS_SECTION, ANTIGRAVITY_RULES, WINDSURF_RULES templates
  gain a short "Keeping this file lean" section pointing at
  `trs audit-docs`. Next `trs init <tool>` seeds the suggestion in
  the user's own rules file.

## Decisions

### Honesty over aggressive compression
rtk's higher compression on some commands came from silently dropping
info (all remote branches in `git branch -a`, merge commits in
`git log`, 109/159 files in `find`). Our responses reformat or group,
never drop. Accepts a percentage-point hit on raw byte count in
exchange for grep-ability and credential safety.

### audit-docs scope
Did NOT implement: full BPE tokenizer (weighted-char heuristic is good
enough), MinHash (SimHash is simpler and sufficient), Flesch reading
ease (not actionable), LLM-based gap analysis (out of scope), SQLite
metrics (JSONL is fine for our use). Shipped with zero new deps.

### Generic-name blocklist for symbol matching
Matching any identifier in a large codebase means names like `data`,
`result`, `value`, `page`, `json` will hit in every project by
coincidence, flooding the report. A ~60-entry blocklist filters the
worst offenders. Non-generic names (RouteBuilder, FormProps,
handleSubmit, etc.) still match meaningfully.

### audit-docs is a user tool, not an agent tool
The agent doesn't run `trs audit-docs` — the human maintaining the
instruction files does, periodically. Positioning is "health check"
not "daily driver". Discoverability gained via `trs doctor` warning
and rules-file template breadcrumbs.

## 2026-04-19 — v0.5.7 continuation: collision check + output-saver

Second continuation session on `feat/v0.5.7-feedback`. Two new features
shipped end-to-end; no breaking changes.

### Feature 1: `trs init` collision check (commits `abec1ee` → `1423e85`)

Problem: `trs init claude` writes our hook unconditionally. If the user
already has rtk (or any other shell-compression tool) installed at the
same event, both fire in sequence → double-compression → corrupt
output. Previous installs were silently destructive.

Solution: pre-install scanner in `src/init_collision.rs`.

- Scans JSON hook configs (`~/.claude/settings.json`,
  `~/.gemini/settings.json`, etc.) for known competitor commands: `rtk
  rewrite`, `rtk proxy`, `rtk git`, `token-optimizer`, `tokopt`.
- Scans rules files (`.windsurfrules`, `.agent/rules/*.md`,
  `~/.codex/AGENTS.md`, etc.) for competitor documentation signatures.
- **Follows `@imports`** — `~/.claude/CLAUDE.md` containing `@RTK.md`
  gets resolved recursively (depth cap 3, visited set for cycles). Real
  rtk users import their rules via `@`; without following, we'd miss
  them.
- **Symmetric scan** — home + project paths always checked regardless
  of `--global` flag. A project-local rtk hook still fires for that
  project's sessions even when we install globally.
- New flags: `--replace` (scrubs competitor hooks from JSON, refuses to
  edit markdown — honest boundary), `--force` (installs alongside,
  documented risk).
- Report recommends `--replace` explicitly: `[recommended]` vs `[risky]`
  markers. Being neutral on a known-bad combination is cowardly.

Validated manually against the developer's own `~/.claude/` (which
imports `@RTK.md`): pre-fix returned clean, post-fix correctly flags
`~/.claude/RTK.md — references RTK - Rust Token Killer`.

### Feature 2: `trs output-saver` (commits `4165b80` → `671d9c9`)

Problem: trs compresses what agents SEE (command output via
`trs rewrite`). Agents still produce VERBOSE replies — preambles
("Sure!"), narration ("Now I will..."), speculative extras — that eat
token budget on the way OUT. We couldn't help with that.

Solution: a new command `trs output-saver` that installs a compact
(~200-token) rules block into each agent's global config, steering
replies toward:

- No preambles / acknowledgment phrases
- No narration of what's about to happen or just happened
- Result-first with optional minimal explanation
- Structured output (bullets/tables/JSON) when the data is structured
- Never invent file paths / function names → `UNKNOWN` or null
- One pass — no iterating on passing code
- Explicit user-override clause so the rules never fight the user

UX is check-first: plain `trs output-saver` runs a read-only scan and
prints what would change. Install requires explicit `--install`.
Remove requires explicit `--remove`. `--print` dumps the raw block for
pipe scenarios.

### Agent coverage — what the research pass revealed

Three categories of global install:

| Mechanism | Agents | How it works |
|---|---|---|
| `@import` | Claude, Gemini | Drop `trs-output-saver.md` + append one line to the root config |
| rules-dir auto-load | Cursor | Drop `.mdc` file in `~/.cursor/rules/`, no edit to any config |
| inline with sentinels | Codex, Windsurf, OpenCode, Kilo, Droid | Append the block wrapped in `<!-- trs:output-saver:start v1 -->` / `:end -->` so re-install replaces between markers |

**Antigravity excluded** by design — no global rules channel, only
per-project (already covered by `trs init antigravity`).

Discoveries during the research pass:

- **AGENTS.md is winning.** Codex, OpenCode, Kilo, and Droid all
  auto-load `AGENTS.md` at a known global path. Droid is an official
  consortium signatory (factory.ai/news/agents-md). That's four agents
  sharing one install pattern.
- **OpenCode plugin API has no prompt-layer hook.** Full event list is
  tool-level + session-level + TUI-level. The rules-file route is the
  only viable global channel.
- **Kilo is a hard-fork of OpenCode.** Same loader, same precedence,
  different directory name (`~/.config/kilo/` vs `~/.config/opencode/`).
  Kilo does expose `experimental.chat.system.transform` for dynamic
  injection — we kept it simple with the file route.
- **Droid exposes `SessionStart` and `UserPromptSubmit` hooks** that
  could inject rules at LLM-call time. Not needed for a static block
  but open for future dynamic work.

### Design decisions worth preserving

- **DRY via macro.** The rules block lives in
  `output_saver_block_literal!()` and expands into both
  `output_saver::BLOCK` (runtime) and the three inline rules templates
  in `init_templates.rs` (compile-time via `concat!`). Rust const
  strings can't be composed across modules — the macro is the clean
  workaround.
- **Sentinels carry a version tag.** `<!-- trs:output-saver:start v1
  -->`. Lets us migrate block content in the future without breaking
  idempotency detection.
- **Testability via `*_with_home` shadows.** Public APIs read HOME
  from env. Test-only `install_agent_with_home` / `remove_agent_with_home`
  variants take an explicit path, so parallel tests don't race on
  `set_var("HOME", ...)`. Three tests round-trip install-remove and
  verify idempotency without touching real env.
- **`replace_between` normalizes newlines.** Without it, each re-install
  appended another `\n` after the end sentinel. Test caught this — the
  fix trims both sides of the splice to exactly one trailing newline.
- **`agent` field name conflict.** The top-level `Cli` struct in
  `src/cli.rs` has `pub agent: bool` (global output-format flag). Using
  `agent: Option<String>` inside `Commands::OutputSaver` caused a clap
  runtime downcast panic. Renamed to `tool` to match `Init`'s
  convention.
