## Decisions

### Import resolution strategy
Unified `resolve_imports` router dispatches based on import shape:
- `./`/`../`/`@/` → `resolve_relative` (path normalization or suffix match)
- Contains `/` → `resolve_module_path` (last 2 then 1 components)
- Plain name → `resolve_by_stem` (stem index lookup)
Discarded: full module-path parsing (too language-specific), AST-based extraction (too slow).

### Go test error message buffering
Go test `-v` outputs error lines BEFORE `--- FAIL:`, not after. Initial design collected errors
after the FAIL marker. Fixed by buffering lines between `=== RUN` and the result line.

### Docs project detection
Projects with >50% `.md`/`.txt` files are classified as docs/skills — dep summary is suppressed
(no source imports to detect, header would be empty noise).

# 2026-04-17 — v0.5.6 qualitative polish: 9-agent integration audit

## Context
Post-v0.5.5 head-to-head benchmark (trs vs rtk 0.35.0) surfaced two
real bugs plus a systemic gap: some cases where rtk "won" were actually
silent information loss (dropped remote branches, truncated commit
messages). Fixed our equivalents honestly (reformat, never drop), then
ran every one of the 9 supported agent integrations end-to-end. Found
and fixed bugs in 6 of the 9. Documented the whole architecture in
`docs/agent-integrations.md`.

## Completed

### Ingest: minimal ≠ aggressive (bug, PR #14)
- `dc5b66d` — both levels fell through the same wildcard arm calling
  `extract_signatures`; now `minimal` delegates to `filter_minimal`
  (strip comments + normalize blanks) while `aggressive` keeps the
  signatures-only behavior.
- labs-tarscli measured: full 334k tokens / minimal 272k / aggressive 18k.

### git branch -a grouping (feature, PR #14)
- `d490ae6` — parser stripped `remotes/` and de-duped but printed every
  branch individually. Added prefix-grouping with `+N more` collapse at
  `COLLAPSE_THRESHOLD=3`, `NAMES_SHOWN_PER_GROUP=2`.
- Compression: native 1148B → trs 262B (77%). Was 14% before.

### git log: remove silent commit-message truncation (fix, PR #14 part)
- `15b4c2a` — two call sites truncated subjects to 57 chars + "..."
  unconditionally. Removed by default. Added opt-in `--truncate N` flag
  for the `parse git-log` handler.
- Default now preserves full messages; users who want tighter output
  pass `--truncate 80`.

### Gemini CLI hook format fix
- `a662c9d` — our `trs rewrite` always emitted Claude Code's
  `hookSpecificOutput.updatedInput.command` envelope. Gemini silently
  ignored that shape — it expects `hookSpecificOutput.tool_input.command`
  with a top-level `decision`. Symptom: hook fired (exit 0) but command
  was never rewritten; `trs stats` showed no entries.
- Added `hook_event_name` dispatch: `PreToolUse` → Claude, `BeforeTool`
  → Gemini, `preToolUse` → Cursor (later), default → Claude.
- Validated with a debug-wrapper that logged stdin/stdout of the hook.

### Factory Droid matcher widening
- `af5b783` — Droid's shell tool is `Execute`, not `Bash`. Our template
  copied Claude's `matcher: "Bash"` verbatim, so the hook registered but
  never matched. Widened to `matcher: ".*"` in a dedicated `DROID_HOOKS`
  template. `trs rewrite` already filters non-shell input, so the wider
  matcher is safe.

### Stale-hook upgrade in merge_json_hook
- `62b83de` — `merge_json_hook` skipped re-writing when any existing
  `trs rewrite` entry was found, which blocked template upgrades (e.g.
  the Droid matcher widening). Now removes any existing trs-owned
  entries across all events and re-adds from the template. User-added
  entries (notify scripts, etc.) survive untouched. Idempotency
  preserved via a before/after snapshot compare.

### OpenCode plugin API + path (fix)
- `b3d783f` — two stacked bugs:
  - Plugin code used `before_tool_call` hook with `ctx.tool` / `ctx.input`.
    Actual API is `"tool.execute.before"` with `(input, output)` and
    `input.tool === "bash"`. Rewritten `OPENCODE_PLUGIN`.
  - `global_dir` was `None`, so `--global` fell back to writing
    `.opencode/plugins/trs.ts` in cwd. Fixed to
    `~/.config/opencode/plugins/`.
- Confirmed end-to-end: plugin auto-discovered, `git status` compressed
  via `trs git status`, stats tracked.

### Kilo plugin path (same fix as OpenCode)
- `e775873` — identical architecture to OpenCode; same
  `global_dir: None` → `.config/kilo/plugins`.

### Pipe/redirect first-segment rewrite (feature, PR #14)
- `7e25b53` — agents routinely add `| head -N`, `| grep X`, `> out.txt`
  to cap output. Old logic skipped rewrite entirely on pipe — defeated
  trs for those very common cases. Now splits at the first operator
  and rewrites only the producer segment (`git status | head -3` →
  `trs git status | head -3`). Semicolons still skip.

### install.sh zshenv targeting
- `6f84f62` — zsh's non-interactive / non-login shells (what IDE tool
  subprocesses usually are) read `.zshenv`, not `.zshrc`. Our previous
  install instructed users to add PATH to `.zshrc`, which left IDE
  subshells broken (`command not found: trs` in Antigravity). Target
  `.zshenv` for zsh instead. `ANTIGRAVITY_RULES` also got a fallback
  section pointing at the absolute `$HOME/.local/bin/trs` path.

### Cursor: move from beforeShellExecution → preToolUse (fix)
- `fb4bafb` + `e797d8a` — Cursor's `beforeShellExecution` hook ONLY
  supports allow/deny/ask decisions; it cannot rewrite the command.
  The rewrite-capable hook is `preToolUse` (lowercase first letter,
  different from Claude's `PreToolUse`). Moved the template;
  introduced the `preToolUse` arm in the dispatch. Added
  `matcher: "Shell"` in a follow-up because Cursor fires `preToolUse`
  for every tool including Read — observed 551 hook invocations in a
  short session before the matcher.

### Post-review cleanup
- `d6301ae` — `apply_truncate` delegates to `helpers::truncate`
  instead of re-doing the char-boundary walk; added a `has_shell_op`
  byte-scan fast path in `maybe_rewrite` (cuts 3-4 `contains` scans
  for ~90% of commands); replaced stringly-typed event dispatch with
  an `HookEvent` enum.
- `1e332ac` — replaced three ad-hoc `truncate_*` helpers
  (`stats::truncate_cmd`, `replace::truncate_line`,
  `parse::extra_services::truncate_str`) with delegates to
  `helpers::truncate`. Each used `&s[..max_len.saturating_sub(3)]`
  which panics on char boundaries — latent UTF-8 bug fixed as a
  side effect.
- `cb35c9f` — renamed `HookEvent::from_wire` to `HookEvent::parse`
  (idiomatic Rust).

## Decisions

### Honesty over compression
When trs and rtk produce different byte counts, verify WHAT each
strips. rtk's "wins" on `git branch -a`, `git log`, and `find` all
came from silently dropping information (all remote branches,
truncated commit subjects, "+N more" with a 50-item cap). We
consolidated via reformatting and grouping instead (prefix grouping
on branches, optional explicit truncation on log, full file list
with summary on find). Net: we lose ~5-10 percentage points on raw
byte compression, but never lose grep-ability.

### Three output envelopes, one input envelope
All hook/plugin clients send `tool_input.command`; three emit
different response shapes. Rather than a single "canonical" output,
dispatch per `hook_event_name`. An enum is cheaper than a
trait-object and exhaustive: `HookEvent::{ClaudePreToolUse,
GeminiBeforeTool, CursorPreToolUse}`. New clients = new variant +
new match arm + new wire-name parse rule.

### merge_json_hook: sweep across ALL events
Template migrations (Cursor `beforeShellExecution` →  `preToolUse`)
leave orphaned entries on the old event name if the sweep is scoped
to the template's events. Now cleans any `trs rewrite` entry
anywhere in the `hooks` object before re-inserting from the
template. Safe because each template writes to its own file — no
cross-tool contamination risk.

### Rules-based: describe, don't force
Codex, Antigravity, and Windsurf have no programmatic hook. The
rules files SHOULD describe what trs is and WHEN to use it (token
minimization context), not try to force every command through trs.
The agent decides. Test prompts for these agents validate the
agent's voluntary choice, not mechanical interception.
