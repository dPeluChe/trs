    fix(parse): what trs lost or invented, found by benchmarking against real output (#166)
    
    * fix(parse): stop pytest inventing test names, and git show altering files
    
    Found by benchmarking trs against real command output instead of fixtures.
    
    `git show <rev>:<path>` prints a file. The classifier returned "no parser"
    for it and its test called that safe, but no parser means the generic pass,
    which collapsed every run of spaces: YAML and Python came back with their
    indentation flattened to one space, and the CI workflow no longer parsed.
    It is now verbatim, like cat, in both the hook and the executor.
    
    pytest never matched a real run. Its fixtures were written by hand with
    `=== FAILURES ===`; real banners are padded to the terminal width, so:
    
    - the failure section was never read, so no error message ever surfaced
    - quiet mode named failures by position: `test_71`, `test_72`
    - the default mode panicked on the padded summary line (an index found in
      the padded line was used to slice the trimmed one)
    - verbose mode dropped the failed list: `name FAILED     [ 98%]` is padded
      too, and the last result was still pending when its failure arrived
    - the "error" shown was the block's first line, `def test_x():`, sliced
      by bytes (a panic on non-ASCII)
    
    Now banners compare their title, quiet failures take their real name from
    the FAILURES section, and the message is the `E` lines plus `file.py:N`.
    New fixtures are captured from real pytest runs, in all three modes.
    
    Claude-Session: https://claude.ai/code/session_01GkgHj56hmkHb2a1syzJwA7
    
    * fix(parse): bun and cargo test failures keep the reason they failed
    
    bun test writes its whole report to stderr, and bun's registry row said
    never to combine stderr, so the bun parser never received any input: trs
    passed the report through raw and added its footer, making it larger.
    
    With the input routed, the parser still read it wrong. Non-TTY bun prints
    a failure's details BEFORE its `(fail)` line; the parser collected the
    lines AFTER one, so the second failure's diff was pinned to the first.
    It now attributes the preceding block, keeps the `error:`, Expected and
    Received lines and the `at file:line:col`, drops the numbered source
    context, and the compact view prints them. 1884 bytes -> 911.
    
    cargo test kept each panic's location and message but not the two values
    assert_eq! prints under it; `(left: 4) (right: 5)` now rides along.
    
    Both are pinned by fixtures captured from real runs.
    
    Claude-Session: https://claude.ai/code/session_01GkgHj56hmkHb2a1syzJwA7
    
    * fix(parse): keep what agents run these commands for, and say where the rest is
    
    Each loss was found by running the real command and comparing, not by
    reading the parser.
    
    - gh pr view: non-TTY gh separates metadata from the body with `--`, not a
      `body:` key, so the body never surfaced; an agent got the title only. The
      whole body is kept now (HTML template comments dropped), plus the change
      counts and any reviewers, assignees or milestone.
    - docker ps: the PORTS column was dropped, the one an agent needs to
      connect. It is cut from the header's offsets, IPv4/IPv6 duplicates folded.
    - git show: the commit header (hash, author, date, message) was dropped;
      it now opens the output. With --stat, per-file counts came from counting
      the +/- bar, which git scales to the terminal (README.md +7/-1 for a
      +45/-1 change), and a file with only insertions was marked new. It now
      prints git's own number per file and no guessed status.
    - git branch -a: groups of 3+ showed 2 names and "+N more", hiding 33 of
      36 remote branches. The braces already save the prefix; all names show.
    - tail: the hook routed `tail -N file` to the log tail, which prefixes lines
      containing "failure" with `ERR`, inside a YAML file. tail of anything but
      a .log is now verbatim, like head.
    
    And one general rule in the executor: when a parser cuts a successful
    output of 16 KB or more by 90% or more, the raw output is saved and its
    path printed, the way failures already are. A large diff summary, ps aux,
    and a CI log stop being dead ends. Also fixes a byte slice in passthrough
    truncation that would panic mid UTF-8 character.
    
    Claude-Session: https://claude.ai/code/session_01GkgHj56hmkHb2a1syzJwA7
    
    * perf(rewrite): stop wrapping ssh
    
    ssh was the command family trs wrapped most in real sessions: 537 times
    in 30 days, saving 1.9% of its bytes. The remote command is opaque to trs,
    so every call paid the wrapper (a process and a capture) for nothing, and
    a long remote session's output was held until it exited instead of
    streaming. `sshfs` and friends are unaffected.
